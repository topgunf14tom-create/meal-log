# 食事記録アプリ（Android）

写真を撮るだけでカロリー・PFCを記録する、自分用の食事記録アプリです。
仕様は `CLAUDE.md` を参照してください。

---

## 1. Claude API の導入手順

写真解析とチェーン店検索には Claude API を使います。Claude.ai の Pro / Max 契約とは**別の従量課金**です（目安：1日3食で月100〜300円）。

1. **アカウント作成**
   <https://platform.claude.com/> を開き、Googleアカウントなどでサインアップします。
2. **クレジットを購入**
   左メニューの Settings → **Billing** でクレジットカードを登録し、クレジットを購入します（プリペイド。最低購入額は画面で確認してください）。
   - **自動チャージ（Auto reload）はオフのまま**にしておくと、使いすぎの心配がありません。
3. **利用上限を設定（おすすめ）**
   Settings → **Limits** で月の上限額（例：$5）を設定します。上限に達するとAPIが止まるだけで、請求は増えません。
4. **APIキーを発行**
   **API Keys** → **Create Key** → 名前（例：`meal-log`）を付けて作成し、`sk-ant-` で始まるキーをコピーします。
   **キーは一度しか表示されません。** 失くしたら新しく作り直してください。
5. **アプリに登録**
   アプリの初回起動画面（または 設定 → Claude APIキー）でキーを貼り付け、「接続テストして保存」を押します。
   「接続OK」と出れば完了です。キーは端末の安全な領域（Android Keystore）にだけ保存されます。

**接続テストで出るエラーの意味**

| 表示 | 対処 |
|---|---|
| APIキーが正しくありません（401） | キーの貼り間違い。コピーし直す |
| クレジット残高が不足しています | Billing でクレジットを購入 |
| モデルが見つかりません | 設定 → モデル を「初期値に戻す」 |
| 利用上限に達しました（429） | Limits の上限額を確認 |

**友人に配る場合**：友人それぞれが自分のアカウントでキーを発行して入力すれば、請求は各自に行きます。自分のキーを教えるのは避けてください。

> メニュー名（Billing / Limits / API Keys）は Console の改修で変わることがあります。見つからない場合は Settings 内を探してください。

## 2. APK の入手（GitHub Actions で自動ビルド）

`main` にpushすると GitHub Actions が自動でビルド・テストし、「最新版」リリースに APK を載せます。

- **ダウンロード先**：<https://github.com/topgunf14tom-create/meal-log/releases/latest>
  スマホのブラウザで開き、`meal-log.apk` をタップしてダウンロード → インストール
- ビルドの状況：リポジトリの **Actions** タブ（緑のチェック＝成功）
- 手動で再ビルド：Actions →「Build APK」→「Run workflow」
- `README.md` などの文書だけの変更ではビルドは走りません

署名鍵は Secret `DEBUG_KEYSTORE_B64` から毎回同じものを復元しています。同じ鍵で署名されるので、新しいAPKは**上書きインストール**でき、記録は消えません。
（鍵を作り直したり Secret を消したりすると上書きできなくなるので、変更しないでください）

### 参考：Windows PC で手元ビルドする場合

Flutter SDK と Android Studio（Android SDK）が入っている前提です。この一式には `android/` フォルダが含まれていないため、初回に `tool/setup.ps1` が生成します。

```powershell
cd meal-log
powershell -ExecutionPolicy Bypass -File tool\setup.ps1
flutter pub get
flutter test
flutter build apk --release
```

出力：`build\app\outputs\flutter-apk\app-release.apk`

## 3. インストールと使い方

1. 上のダウンロード先から `meal-log.apk` をダウンロードしてタップ。「提供元不明のアプリ」の許可を求められたら、ブラウザ（Chrome など）に許可します。
2. 初回起動の案内に沿って APIキーと目標カロリーを設定します。
3. ホームの「記録する」→
   - **食品を検索して記録**：「からあげ」「生中」「すき家 牛丼」のように打つと、チェーン店の公式値・食品成分表・居酒屋や朝食の定番・登録食品から候補が出ます（APIなし・オフライン可）。飲み会は人数をセットすると大皿が 1/N で入ります
   - **写真で判定**：100円玉を料理と同じ面に置き、真上＋斜め45°を撮影。AI（Haiku）は料理名と量（少なめ／普通／多め／大盛）だけを判定し、栄養値はアプリ内のDBで計算します。量が違えばタップで直すだけ
   - **バーコードで記録**：登録済みの商品はすぐ記録。続けて読み取ってまとめて1食に
   - **栄養成分表示を撮る**：端末で読み取り（読めなければHaikuで転記）、確認して登録。次回からはバーコードや検索で呼び出せます
   - **お酒**：ビール・ハイボール・ワイン・日本酒などをサイズと杯数で選ぶだけ（APIキー不要）
   - **DBに無いチェーン店**：公式サイトの栄養成分をWeb検索（Sonnet）
   - **手入力**：自分で入力
   - 記録の確認画面では、品目ごとに「食べた割合」（取り分け・残し）を選べます。右上の☆で「いつもの」に登録すると、ホームから1タップで記録できます
4. 右上のアイコンから **体重**（記録とグラフ）と **設定**（目標・APIキー・モデル・画像圧縮・今月の利用料・バックアップ）を開けます。
5. **InBody**：体重画面の右上「InBody」→「QRを読み取る」で、結果用紙の右下の QR コードを読み取ります（カメラ・写真・貼り付け）。InBody アプリに近い形で結果を表示し、保存すると体重記録にも反映できます。推奨エネルギー摂取量を目標カロリーにすることもできます。対応機種は InBody270 です。
6. **運動の記録**：Strava の過去の記録は、strava.com の「アカウントのダウンロード」で届く zip を、運動の記録の右上の取り込みボタンから選ぶと取り込めます。ルート（地図）・スプリット・ペース・標高・心拍・心拍ゾーン・ベスト記録・年ごとの合計を見られます。
7. **共有**：InBody の結果・体組成の推移・比較、運動のまとめ・詳細・ベスト記録の右上の共有ボタンで、画像と要約を LINE・X・Instagram などに送れます。
8. **記録を楽に**：記録画面の「前回の○食と同じ」「よく食べるもの」はAPIを使わずにすぐ記録できます。「栄養成分表示を撮る」は市販品の表示の数値をそのまま読み取ります。
9. **レポート**：ホームの右上から週・月の平均（摂取・PFC・目標との差・消費・体重）と、AIの振り返りを見られます。体重画面とレポートに、このペースでの1か月後の体重の見込みが出ます。
10. **設定**：1日の区切り（深夜の食事を前日分に）、食品DBの収録状況と登録食品、自動バックアップ（保存先に Google ドライブを選べます）、記録忘れの通知、ホーム画面ウィジェットの案内があります。

6. **ヘルスコネクト連携**：ホームの「連携する」または 設定 → ヘルスコネクト →「自動で取り込む」で権限を許可します。InBody アプリの体重・体脂肪、Strava の運動、スマホの歩数を、アプリを開いたときに自動で取り込みます。
   - 歩数から歩行の消費カロリー（歩幅＝身長×0.45、体重×距離×0.5）を計算し、Strava などの運動中の歩数は除いて運動側のカロリーで数えます
   - 「消費カロリーを目標に上乗せ」がオンなら、その分だけ目標カロリーが増えます
   - 手入力や InBody QR で記録した日の体重は上書きしません
   - 事前に、InBody・Strava 側でヘルスコネクトへの書き込みを許可しておいてください

**食品DBの出典**：「日本食品標準成分表（八訂）増補2023年」（文部科学省）、各チェーン店の公式公表値。DBは `assets/fooddb/` の JSON を差し替えて更新します（過去の記録は記録時点の値のまま）。

**バックアップ**：設定 → データ → エクスポートで、全記録を JSON としてクリップボードにコピーできます。機種変更や再インストールの前にメモアプリ等へ貼って保管してください（写真は含まれません）。

## 4. フォルダ構成

```
lib/
  main.dart               起動・初回案内の判定
  app_services.dart       DB・設定・APIの共有
  core/                   モデルID、料金、PFC計算、日付など
  data/                   SQLite（app_db.dart）、設定、データ型
  services/               Claude API、画像圧縮、解析・チェーン店検索
  features/               画面（home / record / result_edit / weight / inbody / settings / onboarding）
  widgets/                PFCバー・円グラフ、体重グラフ、目標フォーム
test/                     JSON解析・PFC計算・料金計算・キー正規化のテスト
tool/setup.sh, setup.ps1  android/ の生成と設定追記
.github/workflows/        APK 自動ビルド
```
